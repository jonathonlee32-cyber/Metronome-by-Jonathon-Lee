# Metronome

一个简单的 Android 节拍器应用。

## Features

* BPM 调节
* 节拍播放
* 简洁界面
* Android 16 支持
* 无广告，不盈利
* BPM 测速（Tap BPM）：按节奏连续点击 Tap 按钮，同时得到实时 BPM 与平均 BPM，选一个直接应用到节拍器
* 调音器：麦克风实时采集 + 本地基频检测（YIN），识别 A3–B6 范围内的单音，显示音名与音分偏差，±10 音分内变绿；A4 基准可在 432–448Hz 之间调整
* 音准历史轨迹：调音器下方一条横向贯穿的栏目，按时间从右向左滚动最近 8 秒的音分偏差；中间 `±10` 音分是绿色区域、其余为灰色，轨迹是一条连续平滑的白色曲线（不画采样点），换音时先稳定确认再打音名标签、并清掉换音瞬间贴边界的异常点（不出现尖峰），进入 NOISE 时整条轨迹原地停住
* 每日时间记录：自动记录每次练习的开始 / 结束时刻与时长，按日期分组统计今日、本周、累计练习时间
* 竖屏 / 横屏分别适配：竖屏保持原有单列布局，横屏主页面、BPM 测速页和调音器页使用专门的三栏布局（横屏页面整屏显示，不需要滚动）
* 乐谱阅读器：给乐谱项目起名后从系统文件管理器里选一份 PDF，导入成"乐谱项目"（记住名字、PDF 的 Uri 和最近打开时间）；阅读页用系统 `PdfRenderer` 一次一页高清显示，向左滑翻下一页、向右滑翻上一页，点一下阅读区域进 / 出全屏阅读，底部显示"第 3 / 20 页"
* 阅读进度记忆：翻到第几页就立刻记进项目（本地 JSON），退出再进乐谱阅读器会直接回到那份乐谱的第 8 页，而不是回到入口页
* 从图片导入项目：给项目起名后用系统图片选择器选一张或多张图片（可多选），按选择顺序建成"一图一页"的乐谱项目；图片导入时会另拷一份到 App 私有目录，之后离线也能看
* 图片排序：菜单里的「排序图片」进入图片总览（三列缩略图），每张图右上角一个序号圆点 —— 未排序显示灰色"下一个序号"（点哪张哪张就是它的页码），排好显示最终页码并变色；点图片进入查看界面（左右滑动换图），在查看界面点序号会记住这一页并自动翻到下一张，一张接一张排下去；排好后阅读页按新顺序显示，还提供"重置排序"
* 最近项目：乐谱阅读器主页的「最近项目」列出全部乐谱项目（项目名 + 类型 + 最近打开时间，例如"刚刚打开""昨天打开"），按最近打开时间倒序排列；点一下按项目类型进入 PDF / 图片阅读页并刷新最近打开时间，长按弹确认窗口删除项目（只删 App 内的项目记录和导入时拷贝的本地副本，用户原来的 PDF / 图片文件不会被删除）
* 乐谱项目数据库：项目 ID、名称、类型、文件 Uri / 图片 Uri 列表、图片排序信息、当前阅读页码、创建时间、最近打开时间都存进 Room 数据库（底层是系统自带的 SQLite，`filesDir` 同级私有目录），关掉 App、重启手机都还在，完全离线；v4.1 及更早存在 JSON 文件里的老乐谱库会在第一次启动时自动迁移进数据库
* 按键翻页：乐谱阅读页支持外部输入翻页 —— 键盘 / 蓝牙翻页器 / 蓝牙键盘 / `adb shell input keyevent` 发出的**上键、右键、PageDown 都是下一页**，**下键、左键、PageUp 都是上一页**（按下的瞬间翻页，一个按键只翻一页），和左右滑动共用同一套翻页逻辑（`nextPage()` / `previousPage()`），没有第二份实现
* 最近项目操作菜单：长按项目弹出菜单，两个选项 ——「删除」会再弹一次确认窗口，确认后只删数据库里的项目记录和导入时拷贝的本地副本，**用户原来的 PDF / 图片文件不会被删除**；「重命名」弹出输入框，确认后只更新数据库里的项目名称，文件、图片顺序、阅读进度都不受影响；PDF 项目和图片项目都支持
* 录音：主页「录音」入口进去是一个大按钮 —— 没录音时显示「开始录音」，点一下开始（先申请麦克风权限），录音中按钮变红并显示「正在录音 00:12」，再点一下结束并自动保存；文件名按 `yyyymmdd-xxx` 自动编号（例如 `20260926-001`），同一天从 001 顺序往下排、删掉中间某段后空出来的号会被补上，数据库记录 + 磁盘文件一起算，绝不自重名、绝不覆盖已有音频
* 录音只存在本机：用 Android 原生 `MediaRecorder` 录成 MPEG-4 + AAC（`m4a`），写进 App 私有目录 `filesDir/recordings/`（不需要存储权限、不上传云端、卸载才清掉）
* 录音数据库：文件路径、`file://` Uri、文件名称、创建时间、时长、最近播放位置都存进 Room 数据库（`recordings.db`）—— 和乐谱项目的库分开两个文件，录音出任何问题都碰不到乐谱数据
* 最近录音与播放：按录音时间倒序列出全部录音（最新的在最上面），点一下进播放页，长按弹出「删除 / 重命名」；播放页中央是一个大按钮（点一下播放、再点一下暂停，**没有**上一曲 / 下一曲），下面是可拖动的进度条和 `01:25 / 05:40` 这样的「当前时间 / 总时间」，退出播放页会保存"当前录音 + 当前播放时间"，下次进来从上次的位置接着放（离结尾不到 1 秒时从头放）
* 节拍器和录音的关系：**录音时不停节拍器**（节拍器该响继续响）；**播放录音时如果节拍器正在响，先暂停节拍器再开始播放**，播放结束**不**自动恢复节拍器
* 播放页的「分析音准」按钮：v5.0 只显示入口（点一下提示"功能开发中"），音准分析功能留到后续版本
* 录音音准分析（v5.1）：播放页点「分析音准」就会离线分析整段录音 —— **复用调音器那套音高算法**（YIN 基频检测 + 可信度判断 + 跨帧中值平滑，逐时间片跑，没有第二套算法），把整段音频切成 ~46 毫秒一片，每片给出「音名 + 音分 + 是否有效」；分析跑在协程里（解码用 `MediaExtractor` + `MediaCodec`，边解边算、不占 UI 线程、多长的录音都能跑），界面显示进度条和百分比，可以点「后台继续」或直接返回上一页，分析会在后台跑完
* 分析结果：播放页上把「分析音准」按钮换成结果卡片 —— 当前音符（`A4`）、音分（`+12 cent`）、状态（`有效音符` / `NOISE`）、基准音高（`A4 = 440Hz`，点开就是和调音器一模一样的面板，432～448Hz、每次 1Hz）；播放或拖动进度条时这些数值跟着播放位置实时变化
* 基准音高共享：音准分析页改 A4，调音器打开就是新值（两个模块读写同一个 `filesDir/tuner_settings.json`，调音器页面每次可见时都会重新读一次）。改了基准之后，已有分析结果会用存下来的原始频率**立刻重算**音名和音分（不用重新解一遍音频），并写回数据库
* 分析结果持久化：`recordings.db` 里新增两张表 —— `pitch_analyses`（分析 ID、属于哪段录音、基准音高、分析时间）和 `pitch_points`（每个时间点的音名 / 音分 / 是否有效 / 原始频率，主键是"哪次分析 + 第几毫秒"）；一段几十分钟的录音会有上万个点，所以单独成表、不塞进录音表；删掉录音时它的分析结果由外键级联一起清掉
* 数据库迁移：`recordings.db` v1 → v2 只**新建这两张表**，已有录音、播放位置一个字都不动（v5.0 装过的用户升级后录音照旧）
* 新增页面的横屏适配：主页面（横屏时功能入口排成两列）、录音页、最近录音页、录音播放页都支持横屏

### Tuner

主界面中间"调音器"进入。第一次进入会申请麦克风权限；授权后立即开始实时检测，
中央显示当前音名与音分偏差（例如 `A4` / `+5`），偏差在 ±10 音分内时中央区域变绿。
右上角齿轮进入设置，用 `[-] 440 Hz [+]` 调整 A4 基准（432–448Hz，用于十二平均律计算）。
识别不到可靠单音时右上角 `NOISE` 变蓝，中央保留上一次的识别结果。
页面下方是一条**音准历史轨迹**：顶部 `+50`、中央 `0`、底部 `-50` 三条参考线，中间
`-10 ~ +10` 音分是绿色区域（音准较准确），其余为灰色。检测到的每个音高偏差只作为数据点，
界面上把它们连成**一条连续平滑的白色曲线**（不绘制任何圆点／节点），整条曲线按时间从右向
左滚动最近 8 秒，新数据从最右侧进入。音分是相对"最近的音"算的，所以换音瞬间的读数容易在
`±50` 音分边界上来回跳，画出来就是一个不自然的 V 型尖峰。为此换音做了防尖峰处理：新音名要
连续稳定约 140 毫秒（3 帧）才正式确认，确认前不记点也不打标签（一帧、两帧的误识别不会留下
痕迹，`C4 → D4 → C4` 只会有一个 C4 标签），确认时还会清掉旧音符末尾贴着边界的异常点，
让曲线从旧音符最后一个稳定位置直接接到新音符的第一个稳定位置。同一个音之内的真实音高变化
（-5 → +5 → +25 音分）完全不做滤波，逐帧原样显示。进入 `NOISE` 时曲线和标签整体停住，
恢复检测后再从右边缘继续。

## Tech Stack

* Kotlin
* Android SDK
* Jetpack Compose
* 音高检测：全部本地实现，不依赖任何音频识别库或 AI 模型 —— `AudioRecord` 采集单声道 16bit PCM，
  自己实现 YIN 基频检测（差值函数 + 累积均值归一化 + 抛物线插值），配 RMS 与置信度阈值、跨帧中值平滑
* 本地存储：练习记录、调音器设置是 App 私有目录下的 JSON 文件（无第三方依赖）；乐谱项目用 Room 数据库（Android 官方库，底层为系统自带 SQLite）
* 录音与播放：全部用 Android 原生 API —— `MediaRecorder` 录 AAC/m4a、`MediaPlayer` 播放，不引入任何第三方音频库
* 录音的离线音准分析：用系统自带的 `MediaExtractor` + `MediaCodec` 解码成 PCM，再交给调音器同一个 `TunerAnalyzer`（YIN）逐片分析；不引入任何第三方解码库或 AI 模型，完全离线
* 权限：只申请 `RECORD_AUDIO`（调音器采集和录音共用这一个权限）；没有 `INTERNET` 权限，调音器和录音都完全离线、不上传任何音频
* PDF 阅读：用系统自带的 `android.graphics.pdf.PdfRenderer` 逐页渲染，不引入任何 PDF SDK；
  导入的 PDF 会另拷一份到 App 私有目录（`filesDir/scores/`）用于渲染，原 Uri 同时记录在项目里，
  两者都只存在本机、不上传
* 图片阅读：系统图片选择器（`PickMultipleVisualMedia`，不需要存储权限）+ `BitmapFactory` 按 2 的幂次
  降采样解码，一张 4000 像素宽的照片只解出屏幕需要的大小，翻页不卡、也不会撑爆内存；
  缩略图与整页显示用同一套解码，翻走的页立刻回收位图
